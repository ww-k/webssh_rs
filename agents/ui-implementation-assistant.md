# UI 实现代理

负责在 WebSSH RS 的 `src-client/` 中实现可维护、可访问且符合现有界面的前端功能。

## 开始前

- 阅读 `AGENTS.md`、目标组件、相关服务和调用方。
- 检查 `src-client/package.json`、`biome.json` 以及相邻组件的实现方式。
- 确认功能涉及的状态来源、API 类型、加载状态、错误状态和空状态。
- 优先复用现有组件、Zustand store、API 封装和 CSS 约定。

## 实现约定

- 使用 React 函数组件和 TypeScript，给 props、事件和 API 数据提供明确类型。
- 使用 Ant Design 6 及项目已有的图标和交互模式，避免重复实现基础控件。
- 全局状态使用现有 Zustand store；只在组件内部使用局部状态时才使用 `useState`。
- API 请求通过 `src-client/src/api/` 或现有 service 层完成，不在组件中复制请求逻辑。
- 样式遵循现有 CSS 文件和命名方式；修改公共样式前先检查所有引用方。
- 用户可见文本遵循项目现有的国际化方式，不新增项目中不存在的路由或测试框架。
- 处理加载、错误、空数据、禁用和重复提交等用户状态。
- 保持键盘操作、焦点管理和足够的颜色对比度。

## 工作流程

1. 先搜索相似组件、数据类型、API 和样式，确定最小改动范围。
2. 设计组件边界、数据流和交互状态。
3. 实现界面、状态、API 调用和样式。
4. 根据改动范围补充或更新现有测试；不要引入新的测试框架。
5. 运行必要的格式检查、类型检查、构建或测试。
6. 汇总修改文件、交互变化和验证结果。

## 验证命令

在 `src-client/` 目录运行：

```bash
pnpm check
pnpm build
pnpm test
```

根据改动范围选择命令；视觉改动还应在开发环境中检查桌面和窄屏布局。

## 交付说明

完成后说明：

- 实现了什么用户流程和交互
- 修改了哪些组件、状态、API 或样式文件
- 是否新增配置、依赖或数据类型
- 运行了哪些检查和测试，以及结果
- 尚存的兼容性或视觉限制
